# Maintenance Loop

本文件定义一次完整的、基于证据的现有功能维护闭环。任何智能体进入本项目后，若任务是"维护现有功能"，都应执行本 Loop。本 Loop 只维护现有功能，不承担新功能开发。

一次 Loop 的完整流程：

```
Observe → Evidence → Decide → Execute → Verify → Record
```

---

## 0. 入口前置条件

- 只修改已存在的功能，禁止新增功能、大规模重构、依赖升级。
- 每一轮 Loop 只处理一个最高价值问题。
- 所有操作必须以可复现证据为前提，禁止猜测式修改。
- 本仓库另有权威项目规范 `AGENTS.md`（模块清单、产品不变量、测试领域、验证纪律）与中文说明 `CLAUDE.md`，与本文件冲突时以 `AGENTS.md` 为准，并在此记录冲突。

---

## 1. Observe（观察，禁止修改代码）

执行任何修改前，必须先顺序读取：

1. `.agent/rules.md` — 项目级 Agent 边界（必须/禁止）。
2. `.agent/memory.md` — 长期项目知识（架构、已确认设计、已验证区域）。
3. `.agent/history.md` — 最近若干次 Loop 记录，避免重复处理已完成问题。

随后检查当前事实状态（只读操作）：

- 当前工作区状态：`git status`（是否有未提交修改、未跟踪文件）。
- 最近提交：`git log --oneline -10`。
- 最近修改：`git diff --stat`（未暂存改动范围）。
- 测试状态：最近一次 `swift test` 结果（失败项、数量、是否稳定复现）。
- 已知问题：`AGENTS.md`、`VERIFICATION.md`、`QA_CHECKLIST.md`、`README.md` 中记录的已知限制与未验证项。
- 用户反馈：会话上下文、最近提交说明、issue/PR 描述。
- TODO/FIXME：`rg -n "TODO|FIXME|HACK" Sources Tests docs`。
- 错误信息：应用日志（`./script/build_and_run.sh --logs` / `--telemetry`）、系统日志中的本应用错误。

观察阶段禁止：直接修改任何代码。

---

## 2. Evidence（证据判定）

只有存在以下有效依据之一，才允许进入 Decide 阶段：

- 可复现 Bug（有最小复现路径）
- 测试失败（`swift test` 可稳定复现）
- 明确的行为异常（相对产品不变量，见 `AGENTS.md` "Product Invariants"）
- 用户反馈（有具体场景）
- 稳定性风险（崩溃、死锁、数据丢失、状态不一致，有代码路径证据）
- 性能问题（有可测量证据）
- 测试缺口（某关键路径完全没有测试，且属于 `AGENTS.md` 测试领域表范围）

以下情况**不算有效证据**，禁止修改：

- 个人代码风格偏好
- 猜测的潜在问题（无复现、无代码路径证据）
- "顺手优化"类改动

**没有足够证据：不修改，结束本轮。**

---

## 3. Decide（决策：只选一个）

证据成立后，从中选择一个最高价值问题。优先级（从高到低）：

1. 用户影响 Bug
2. 稳定性风险
3. 数据正确性风险
4. 性能问题
5. 错误处理问题
6. 测试缺口
7. 可维护性问题

问题选择要求：

- 有明确依据（对应第 2 节的有效证据清单）。
- 可以验证（能用测试/构建/验收流程证明结果）。
- 修改范围可控（小 diff、不牵连无关模块）。

允许连续维护同一个模块，但每轮必须满足：有新的证据，且不是重复处理 `history.md` 中已完成的问题。

必须避免：

- 重复处理 `history.md` 中已完成的问题（先查最近记录）。
- 纯代码风格调整（无行为变化、无证据）。
- 没有验证方式的问题（无法用测试/构建/验收流程证明结果）。

**如果本轮没有高价值问题：结束本轮，不强行修改。**

选定问题后，在 `history.md` 中追加一条"进行中"记录（Loop 编号、问题、证据），再进入 Execute。

---

## 4. Execute（执行最小必要修改）

- 小范围 diff，只改与选定问题直接相关的代码。
- 保持现有架构与目录分层（`App/` `Core/` `Shared/` `System/` `UI/`）。
- 保持兼容行为：不破坏产品不变量（`AGENTS.md` "Product Invariants"）。
- 修改被 Widget 复用的文件（`AGENTS.md` 的 widget 文件表）时，保证两种编译上下文兼容，必要时同步 `CodexMonitorWidgetExtension.xcodeproj/project.pbxproj`。
- 修改持久化模型时，保持新旧格式兼容（`PersistenceEnvelope` 校验与迁移约定，见 `memory.md`）。

禁止：

- 新增功能
- 大规模重构
- 无关优化
- 删除测试
- 修改测试以绕过问题（只允许为"测试本身有缺陷"的情况修正测试，且需在 Record 中说明）
- 随意升级依赖
- commit / push / 发布 / 部署

---

## 5. Verify（验证，禁止未验证宣称完成）

按项目既有验证流程执行，范围从窄到宽：

1. 最窄相关测试：
   ```bash
   swift test --filter <TestClass>
   swift test --filter <TestClass>/<testMethod>
   ```
2. 全量测试：
   ```bash
   swift test
   ```
3. 构建：
   ```bash
   swift build -c debug
   ```
4. 涉及打包、签名、安装、Widget 集成时，运行统一验收流程：
   ```bash
   ./script/build_and_run.sh --verify
   ```
   注意：该命令会停止现有 App 并替换已安装 bundle。
5. 涉及菜单栏 / Popover / Widget 可见行为时，对照 `QA_CHECKLIST.md` 逐项手动检查，并如实报告未执行的手动检查项。
6. 涉及持久化、身份边界、RPC、并发、生命周期时，覆盖对应的失败/取消/恢复/关闭路径测试（参考 `AGENTS.md` Review Guidelines）。

验证纪律：

- 禁止未验证即宣布完成。
- 禁止隐藏失败：验证失败必须如实记录并继续处理。
- 如果验证失败，基于新的错误信息回到 Execute（小步修正），不要无依据重试。
- 如果某个必需验证流程无法运行（如无签名证书、无 `codex` 可执行文件），报告原因和确切未验证项。

---

## 6. Record（记录）

每次 Loop 结束后更新 `.agent/history.md`，追加该 Loop 的完整记录，字段：

- **Loop 编号**（自增整数）
- **日期**
- **问题**（一句话）
- **证据**（复现步骤 / 失败测试 / 观察到的行为）
- **原因**（根因分析）
- **修改**（改动文件与范围，diff 统计）
- **验证**（运行了哪些命令、结果）
- **剩余风险**（未覆盖路径、未执行的手动检查、遗留问题）

如果本轮**没有修改**（无有效证据、无高价值问题或验证不通过），同样必须追加记录，字段：

- **检查范围**（Observe 阶段检查了哪些区域）
- **未发现高价值问题的原因**（按第 2/3 节证据与优先级判定，为何不选）
- **验证状态**（运行了哪些检查及其结果；未运行的说明原因）

"不修改"是有效的维护结果，但必须留下记录，供后续 Loop 避免重复检查。

同时：

- 若产生了新的稳定架构知识或已确认设计，合并进 `.agent/memory.md`（只保留长期信息）。
- 若项目边界/验证流程发生变化，更新 `.agent/rules.md` 或 `loop.md` 中的命令清单。

---

## 7. history.md 维护规则

- `history.md` 只保留最近若干次 Loop 记录（建议最近 10 次）。
- 更早的记录移动到 `.agent/archive/`（按 Loop 编号或日期命名，如 `loop-001-015.md`）。
- 日常 Loop 不主动读取 `.agent/archive/`，仅当需要回溯历史根因时按需查阅。
- 归档时在 `history.md` 中保留一条跳转索引。

---

## 8. 本轮结束判定（Definition of Done）

一次 Loop 只有在以下条件全部满足时才算完成：

- [ ] 选定问题有有效证据
- [ ] 修改最小、符合架构与不变量
- [ ] 全部相关验证通过（或已如实记录无法运行的验证项与原因）
- [ ] `history.md` 已追加完整记录
- [ ] 未 commit / push / 部署

如果没有发现问题或验证不通过，如实结束本轮并说明状态。
